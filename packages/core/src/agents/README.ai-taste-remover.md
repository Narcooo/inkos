# AI 味去除功能（qu-ai-wei）

基于 [qu-ai-wei skill](../../../my-novel/1.md) 的核心逻辑，为 inkos 项目集成的去 AI 味独立 Agent。

## 功能概述

这个 Agent 用于识别并去除简体中文写作中的 AI 生成痕迹，让文字读起来自然、像真人写的。

### 核心特性

- ✅ **真人文本检测** - 先判断是不是真人写的，是则停手
- ✅ **语体识别** - 支持 9 种语体（社交/自媒体/商务/书面/特稿/品牌广告/学术/公文/高考作文）
- ✅ **51 条 AI 腔模式检测** - 基于密度原则，不机械匹配
- ✅ **保守编辑策略** - 句子没坏就不优化，避免越改越差
- ✅ **保留毛边** - 至少保留一处真人痕迹（主观判断/具体感受）
- ✅ **不发明事实** - 终稿里的具体信息原文都得有依据

## 使用方式

### 1. 独立调用

```typescript
import { AITasteRemoverAgent } from "./agents/ai-taste-remover.js";

const agent = new AITasteRemoverAgent(ctx);

const result = await agent.removeAITaste({
  content: `随着科技的不断发展，AI 技术已经深入到我们生活的方方面面。
            值得一提的是，这项技术不仅提高了效率，更重要的是为人们带来了便利。`,
  targetStyle: "conservative", // 保守策略
});

console.log(result.revisedContent);
```

### 2. 集成到写作流程

```typescript
// 在章节生成后自动调用去 AI 味
const writerOutput = await writer.writeChapter(...);

const aiTasteRemover = new AITasteRemoverAgent(ctx);
const humanizedResult = await aiTasteRemover.removeAITaste({
  content: writerOutput.content,
  targetStyle: "conservative",
  register: "written",
});

// 使用去 AI 味后的版本
return humanizedResult.revisedContent;
```

### 3. 指定语体

```typescript
const result = await agent.removeAITaste({
  content: input,
  register: "business", // 商务语体
  targetStyle: "aggressive", // 激进策略
});
```

## API 文档

### 输入参数

```typescript
interface RemoveAITasteInput {
  content: string;                    // 待处理的文本
  targetStyle?: "conservative" | "aggressive";  // 保守/激进策略
  register?: RegisterType;            // 语体类型（可选，会自动检测）
  language?: "zh" | "en";             // 语言（目前只支持中文）
  temperature?: number;               // LLM 温度（默认 0.3）
}
```

### 输出结果

```typescript
interface RemoveAITasteOutput {
  revisedContent: string;             // 修改后的文本

  patternsFound: AIPattern[];         // 发现的 AI 腔模式
  polishReport: PolishReport;         // 打磨报告
  tokenUsage?: TokenUsage;            // Token 使用统计
}
```

## 核心原则

### 1. 门检机制（第负一步）

在改写之前先判断输入是不是真人已经写好的文本。如果是，**停手**，最多只做格式清理。

**真人文本的强信号：**
- 自纠/犹疑语气（"我忘了""我猜啊""说不上来"）
- 浓厚地域词（"内/那""咋""嘅"）
- meta-irony/自嘲（"用比较酸的话说""我知道这话鸡汤"）
- 具体到只有这个人的细节（具体书名、人名、金额）
- 已知作家的可辨识口吻（金庸、王朔、汪曾祺等）

### 2. 语体识别（第零步）

不同语体的"AI 腔"标准完全不同。先识别语体，再选规则子集。

**判断不准时，默认是「书面/一般」**（不是「社交/口语」）。

### 3. 保守编辑原则

- **不伤害原则** - 句子没坏就不要"优化"它
- **保持原味** - 保留原文的语气、节奏和角色声音
- **一次修复** - 同一段落不要叠加多个修复
- **尊重上下文** - 不要删除铺垫、呼吸段或过渡段

### 4. 密度原则

单独出现不算 AI 腔；短段落内反复堆叠、脱离具体内容才是 AI 腔。

**判断三问：**
1. **密度** - 在短段落（<200 字）内出现几次？三次以上基本确认
2. **落地** - 这个修辞紧扣具体内容吗？还是换成任何话题都适用？
3. **负载** - 删掉之后原意会丢失吗？不会就是装饰性

### 5. 不发明事实

终稿里的具体数字/事件/人物/引用，原文都得能打钩。打不到 → 删除，或标 `[改写者补注，请核对]`。

### 6. 保留毛边

至少保留一处真人的痕迹：
- 个人化表达（主观判断/不完美句）
- 具体的感受（不是"让人担忧"，是"凌晨三点看到红点还没消"）
- 圈层语境特有表达

## 检测的 AI 腔模式（51 条）

### A. 内容拔高 (#1-6)
- 过度拔高意义（具有重要意义/里程碑/谱写新篇章）
- 空洞强调（值得一提的是/不可否认/毋庸置疑）
- 时代背景套路（随着...的不断发展）
- 模糊权威归因（专家表示/业内人士认为）

### B. 语言模式 (#7-20)
- AI 高频词（赋能/助力/打造/闭环/抓手）
- 华丽意象堆砌（璀璨/熠熠生辉/画卷）
- 的的不休
- 滥用"进行+V"
- 破折号高密度

### C. 修辞模式 (#21-25)
- 四字成语机械堆叠
- 排比段硬套
- 总 - 分-总僵化结构

### D. 交流模式 (#26-29, #51)
- 客服腔（希望对您有帮助）
- 过度迎合（您问得非常好）
- AI 免责声明
- 空洞积极结尾

### E. 填充模糊 (#30-32)
- 冗余书面化短语
- 过度模糊限定

### F. 翻译腔 (#33, #39-42)
- 翻译腔残留
- 有中文译法却留英文

### G. 篇章节奏 (#35-36, #43-44)
- 句长均质化（机关枪段）
- 指代不敢省

### H. 平台场景与文体 (#37-38, #49-50)
- 自媒体套路
- 文学 AI 味

### I. 幻觉与格式 (#45-48)
- Markdown 格式残留
- 编造引用/AI 源 URL

## 语体激活矩阵

不同语体激活不同的规则子集：

| 规则类别 | 社交 | 自媒体 | 商务 | 书面 | 学术 | 公文 | 高考 |
|----------|------|--------|------|------|------|------|------|
| 内容拔高 | ✅ | ✅ | ✅ | ✅ | 部分 | ❌ | ❌ |
| AI 高频词 | ✅ | ✅ | ✅ | ✅ | 部分 | ❌ | ❌ |
| 修辞 | ✅ | ✅ | ✅ | ✅ | 部分 | ❌ | ❌ |
| 客服腔 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 翻译腔 | ✅ | ✅ | ✅ | ✅ | 部分 | 部分 | 部分 |

**关键含义：**
- **学术语体**：`进行+V`、`性/化` 后缀、被动语态是规范表达，不改
- **公文语体**：几乎只改客服腔，公文有其 established 写法
- **高考作文**：比公文还要保守，几乎只改客服腔和格式幻觉

## 输出示例

### 输入（AI 腔浓）
```
随着科技的不断发展，AI 技术已经深入到我们生活的方方面面。
值得一提的是，这项技术不仅提高了效率，更重要的是为人们带来了便利。
不可否认，未来 AI 将在更多领域发挥重要作用，谱写新的篇章。
```

### 输出（去 AI 味后）
```
AI 技术已经渗透到生活的各个角落。
它确实提高了效率，也给人们带来了便利。
未来，AI 会在更多领域发挥作用。
```

### 门检声明
```
【门检】判断：AI 生成文本 | 证据：["AI 腔信号：时代背景套路", "AI 腔信号：空洞强调", "AI 腔信号：过度拔高"]
```

## 打磨报告

终稿之后必须附打磨报告（仅描述，不做审美评级）：

```
【打磨报告】
· 动词强化：[若干处] · 例：原文「发挥作用」→ 终稿「管用」
· 节奏重塑：[若干处] · 例：原文「XXX」→ 终稿「YYY」
· filler 切除：[一些/实际上/本质上]
· 抽象换具体：[无]
· 语序归位：[若干处]
· 语体匹配档位：[书面/一般]

可观察指标：
- 具体名词：[N 处]
- 第一人称代词：[N 处]
- 引用原话：[N 处]
- 段长变异：[最短 X 字 / 最长 Y 字]
```

## 与原有 AI 味检测的区别

inkos 项目已有 AI 味检测与修改功能（`detector.ts` + `detection-runner.ts`），与这个 Agent 的区别：

| 特性 | 原有检测 (detector) | 新增 Agent (ai-taste-remover) |
|------|---------------------|-------------------------------|
| **检测方式** | 调用外部 API（GPTZero/Originality） | 基于规则的本地检测 + LLM 改写 |
| **修改策略** | 循环改写直到 API 分数达标 | 一次性保守修改，保留毛边 |
| **语体感知** | 无 | 9 种语体识别，不同语体不同规则 |
| **门检机制** | 无 | 有（真人文本停手） |
| **适用场景** | 批量自动化处理 | 精细化的单文本处理 |
| **输出报告** | 检测分数 | 打磨报告 + 模式检测 |

**建议用法：**
- 批量写作 → 用原有检测（自动化）
- 单文本精修 → 用新 Agent（更细腻）
- 两者可结合使用
